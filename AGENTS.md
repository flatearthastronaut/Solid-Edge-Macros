# Project Guidelines

## Working Agreements
- Use the step-by-step review approach for all future drawings. Complete, check, and save one stage, show the result, and ask whether it looks correct. Wait for the user's approval before starting the next stage; an approval applies to the completed stage, not to all remaining detailing.
- Default drawing stages are: (1) drawing views, section/cutting-plane layout, and shaded ISO; (2) centerlines and center marks; (3) chamfer and radius/fillet dimensions; (4) linear, diameter, and angular dimensions; (5) notes and feature-linked thread/hole callouts. Let the user direct any additional stages or explicitly change/combine the sequence. Resolve requested corrections within the current stage before advancing.
- Preserve approved work while adding the next stage. Check placement for overlaps and crossings, maintain model associations and reference presentation, and verify saved results before presenting them for review.
- Record new general detailing rules in these project guidelines as the user supplies them, and apply them to future drawings. Keep part-specific exceptions scoped to that job; the user's latest explicit instruction takes precedence over an older rule.
- When a reference drawing is available, match its applicable detailing, dimension precision, and tolerance format. A different model nominal alone is not a reason to increase displayed precision: for example, the user approved displaying a .625-inch model OD as .63 to match a two-place reference and its title-block tolerance. Retain the exact model-linked measurement; do not override the value or alter model geometry to match rounded text.
- For future Solid Edge drafts, use the normal (new designs) draft template.
- Start drawings at 1:1 scale on a B-size sheet. Enlarge the view scale if needed for uncrowded dimensions. C, D, E, and EE sheets may be used when necessary, but ask the user before changing sheet size.
- Always use third-angle projection for drawings.
- Keep section views aligned with their parent/projected views.
- Isometric drawing views should be shaded. Add centerlines/center marks to the orthographic and section views, not to the isometric view.
- For any part first machined on a lathe, use the cap references as the layout standard: aligned end and longitudinal section views, grouped diameter banks, axial dimensions near their corresponding ends, and clear leaders; adapt the actual dimensions and notes to the part and operation.
- Start with linear dimensions of outside features above the section and linear dimensions of internal features below it. Place outside-feature lengths below only when the upper dimensions become crowded. Select extension origins on the corresponding side of the view.
- Match dimension presentation to `DraftingStandards/detailing example 1.dft`, using `DraftingStandards/ReferenceDimensionStyle.cs` and its audited property snapshot. Match Lines and Coordinate settings and the teal Driven dimension color (8421376); retain the job's required units, precision, and tolerances.
- Attach manufacturing dimensions to physical model geometry, excluding coincident hidden cutting-plane/Base construction graphics. Verify the parent edges and extension origins after reopening; a correct measured value alone does not prove a correct attachment.
- Also match the reference's centerlines, center marks, cutting planes, text, leaders, callouts, surface-finish symbols, tolerance formatting, and title-block field styles. Use `DraftingStandards/ReferenceAnnotationStyle.cs` and `annotation-presentation-standard.xml`, choosing the appropriate annotation role and inch-only versus dual-unit Smart Depth format. Preserve actual limits, engineering content, feature links, section direction, and view alignment; enlarge/reposition text boxes when necessary instead of shrinking the reference text size.
- Add native Horizontal or Vertical constraints to all horizontal/vertical lines created in sketches, cutting-plane profiles, and other editable drafting geometry. Use each profile's local coordinates; do not substitute visually aligned endpoints for constraints.
- When a cutting plane passes through the model's Base coordinate-system origin, add a native point-on constraint between the model-linked projected Base origin and the cutting-plane segment. Use `DraftingStandards/BaseOriginConstraints.cs`; retain Horizontal/Vertical constraints and verify the Base connection after view movement and save/reopen. Matching coordinates alone is insufficient.
- Create chamfer callouts with native Chamfer Dimensions, not manually typed notes.
- For repeated equal-size chamfers or radii/fillets, create only one native dimension per size and set its Dimension Prefix Subfix to `TYP(x)`, where x is the total number of physical occurrences. Count continuous revolved features once, not twice because they appear on both sides of a section.
- Create hole callouts with the native Callout command, using model feature references and Smart Depth variables for hole/thread sizes and depths.
- For simple drilled-hole callouts, use the saved `HC -DRILL` note for inch-only and `HC -DRILL M[I]` for dual dimensions. Apply recognized special-hole notes first, preserve native size/depth/quantity links, and leave conflicting matches for review.
- Set hole-callout horizontal alignment from its break-line direction: a break line extending left uses left-aligned text; one extending right uses right-aligned text. Preserve the leader geometry and model attachment.
- In Turbo Callout, preserve the saved `(%QC)PLC'S EQ. SP. AS SHOWN` line when the quantity exceeds one. When the quantity is one, omit the entire TYP and associated PLC'S EQ. SP. quantity lines, including a combined TYP/spacing line. Keep `%QC` linked for retained quantity lines and preserve all other manufacturing wording.
- In Turbo Callout, retain the exact separate line `(FOR X S.H.C.S.)` on counterbore notes in both inch-only and dual modes, leaving the literal `X` as saved.
- In Turbo Callout, reuse clearly named styles for matching formats instead of adding a GUID style for every note. Consolidate previous macro styles while preserving formatting, units, tolerances, leader placement, and model links; retain styles still used by other objects.
- For standard threaded holes and simple SHCS counterbores in Turbo Callout, use only `(%QC)PLC'S EQ. SP. AS SHOWN` as the quantity line in both unit modes, without a TYP line. Apply this rule to new and existing macro notes, omit the spacing line at quantity one, and retain the counterbore's separate `(FOR X S.H.C.S.)` line.
- For other hole families, add `TYP(%QC)` as a separate line to generated Turbo Callout notes and existing macro notes that do not already have a TYP line, unless the native quantity is one. Remove the entire line for literal or evaluated `TYP(1)`, without leaving a blank line. Preserve other TYP quantities and keep retained `%QC` values model-linked; reevaluate omission when the macro is rerun.
- For Turbo Callout, apply precision to each machining value: inch values have one more decimal place than metric values. Use two inch places for drill diameters/depths, counterbore and spotface depths, dowel-pin and spring-pin depths, and thread depths. Use four inch places for dowel-pin diameters and three for spring-pin diameters. O-ring face-seal recess depths retain three-place inch limits (.054/.050), with two metric places. Preserve native model links, exact dimensions, thread designations, and manufacturing tolerances; this rule supersedes the older whole-note precision rules for this macro.
- Keep each Turbo Callout note as a single native callout. For dual notes, use Greg's saved-note fallback: type the three- and four-place diameter limits and their metric equivalents while retaining parametric drill diameters and ordinary depths at two inch/one metric place. The three-place face-seal .054/.050 depth limits also use fixed text. Keep high-precision values parametric in inch-only notes, where per-field rounding works. Do not add grouped callouts or silently regenerate existing fixed values when the model changes.
- In Turbo Callout, typed stacked tolerance values must use the full surrounding note text height (.125 inch in the standard notes). Set their tolerance-height ratio to 100%, preserving the actual typed values, decimal places, note height, model links, and leader placement. Apply the correction to new and existing macro notes.
- For hole tables, use `%F1` for standard threaded holes, counterbores, and countersinks; `%F2` for dowel-pin holes and #2 SAE O-ring ports; `%F3` for Koenig plug holes that block hydraulic/air passages; and `%F4` for #4 and #6 SAE O-ring ports. Identify special holes using known diameter/depth combinations from the company's standard design charts, not feature names or the current row's possibly incorrect callout.
- A .052-inch counterbore depth identifies an O-ring face-seal recess for a 1/16-inch cross section; it is not an SAE-port identification rule. Preserve model dimensions and flag unmatched or conflicting standard entries for review.
- Match O-ring face seals against the saved `Face Seal-` recess diameters and .052 depth, using the native `%F3` counterbore format only when it preserves linked sizes and .054/.050 depth limits. In hole-table previews, label SF dowel pins as slip fit and PF dowel pins as press fit.
- Identify SAE O-ring port size from the thread together with its spotface and chamfer: 5/16-24 is #2, 7/16-20 is #4, and 9/16-18 is #6. A thread designation alone is not sufficient. Use Solid Edge's saved hole-creation settings as the source for the Koenig plug sizes used here; there is no separate Koenig chart.
- Recognize both SAE-port modeling conventions: newer ports have an accurately modeled countersink plus a chamfer; older ports used one larger chamfer. Do not require the newer two-feature entrance on an older valid port.
- Hole-table automation must leave oddball/unmatched holes and conflicting matches unchanged and flag them for review. Do not force an unknown hole into `%F1` or another known category. Preserve existing custom row notes and tolerances unless their replacement is explicitly requested.
- CV plug is the former name for Koenig plug. Koenig/CV plug seat depths and SAE-port counterbore/entrance depths can be changed for the part; do not require exact saved-preset depths for either family. Use standard diameters with native hole type and available thread evidence, preserve actual model-linked depths, and flag ambiguous or conflicting matches for review.
- Recognize 3/8-inch spring-pin holes from their saved standard and #8 SAE ports from their saved spotface/entrance geometry and 3/4-16 thread information. SAE spotface depths may vary from the saved settings; preserve the actual modeled depth, including .030 or .052 where the full diameter/type evidence identifies a port.
- In hole-table review windows, put a thick red outline around a hole-letter group containing more than one hole type and show this exact warning at the top: "Multiple hole types found with the same selected hole size". Determine mixed types within each table, independently of row status or checkbox selection.
- When a hole table's shared `%F4` counterbore definition explicitly describes a #4 SAE port, use a separate model-linked callout from the saved `SAE Port #6` text for #6 rows. Do not change the shared definition and thereby relabel #4 rows.
- Use two inch decimal places for all SAE #6 and #8 hole-callout dimensions, preserving thread designations, actual model values, and metric precision independently.
- Add the saved size-specific P.F. or S.F. note as a separate line in dowel-pin callouts, retaining the fit limits. Every Koenig plug callout must include the exact separate line "(DO NOT CHAMFER HOLE)".
- Hole-table callout values are inch-only. Show P.F./S.F. fit amounts using the saved inch value without a metric equivalent or brackets; preserve the actual pin designation (for example, 10mm DOWEL) and the model-linked fit limits.
- Include the thread machining diameters (external major and internal minor diameters as applicable). External thread diameters are modeled nominally; set native upper tolerance to -.002 inch and lower tolerance to -.006 inch, both negative. Do not change the nominal model diameter to represent the manufacturing limits.
- When the user specifies a dimension as two-place, three-place, etc., this always means the number of digits after the decimal point in the inch value. Do not change metric precision to match that instruction.
- Use two inch decimal places for counterbored-hole and bolt-circle dimensions, three for threads and hydraulic/air holes, and four for dowel-pin dimensions. Apply the precision to native dimensions and feature-linked callout formatting; preserve thread designations and explicit fit tolerances.
- Chamfer and radius/fillet inch values use two decimal places, except values of .015 inch or less use three. Preserve metric precision independently.
- Ask clarifying questions when the task scope is unclear.
- If a detailing step needs prolonged investigation, stop after a brief focused troubleshooting attempt and ask Greg for guidance instead of repeating speculative fixes.
- Keep pull requests small, focused, and reviewable.
- Do not look into files outside of the project directory and its sub-directories
- When making changes to macro programs compile them after making modifications and drop the executable file in a sub-directory called "Compiled Executables"
- After compiling a new version of the macro add all files you've changed to a git commit using the command "git add .". Then execute "git commit -m "XXXXXXX" where XXXXXXX is a short description of changes made. Then push the commit using "git push origin main".

## Code Style
- Ensure all new features include appropriate unit or regression test coverage.
- When creating Solid Edge Macros refrence the examples found in the folder "SDK_2026_2510_English". Ensure you are using best practices for memory handling and overall macro stability and reliability
- Ensure that you code is efficent and contains detailed comments explaining how the code works and why you made certain decisions.
- Whenever possible make sure your code is using compute power efficently.
